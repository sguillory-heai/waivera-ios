# 0002: Local packages, XcodeGen and a local source of truth

Status: Accepted (2026-10-27)

## Context

The app must feel instant on poor connections and survive reconnects without losing
messages or showing stale state. It is also being built without a Mac, so the project
must be reviewable as text and buildable from the command line in CI.

## Decision

- Code lives in local Swift packages under `Packages/` (`WaiveraAPI`, `WaiveraRealtime`,
  `WaiveraDesign`, then one package per feature). The app target only wires them together.
  Features depend on core packages, never on each other.
- The Xcode project is generated by XcodeGen from `project.yml` and not committed. Project
  changes review as YAML and never cause `.pbxproj` merge conflicts. Tuist was considered;
  XcodeGen is a single binary with no cache or account and is enough for one app target.
- Swift 6 language mode with complete concurrency checking; the app target defaults to
  main-actor isolation.
- State lives in `@Observable` models fed by repositories. SwiftData is the source of truth for
  anything a screen lists; writes are optimistic and retried from an outbox.
- The chat hub sits behind `RealtimeClient`. The implementation owns backoff
  (`ReconnectPolicy`, matching Android), rejoins open conversations and resyncs over REST
  after every reconnect.

## Consequences

- Contributors run `xcodegen generate` after cloning and after pulling a `project.yml` change.
- Foundation-only packages are tested on Linux in seconds; SwiftUI and the app are tested on macOS.
- Every feature model needs a fake in `TestSupport` and tests for loading, empty, error and reconnect states.
